# SPC700 CPU and snapshot foundation

`SPC700` implements all 256 sound-CPU opcodes in Swift. `SPC700Bus` supplies
byte reads, byte writes and idle clocks. Each call represents one clock; dummy
reads are real reads and can have device side effects. A bus must perform the
access before advancing attached devices. The core does not map APU ports,
timers, the IPL overlay or DSP registers.

This ports Gustavo Franco's MIT-licensed
[sony-spc700-python](https://github.com/gufranco/sony-spc700-python/tree/91c0576a00bd7eae09847f8f34bd4ff2dfc46773),
specifically `spc700/core.py` and `spc700/opcodes.py`. The license is in
`ThirdParty/sony-spc700-python-LICENSE` and copied into the app bundle's
`Contents/Resources/Licenses`. Python and libgme are not runtime dependencies.

## Execution contract

Construct a CPU with a bus and explicit `SPC700.Registers`. `step()` executes
one instruction and returns its clocks. `run(cycles:)` executes whole
instructions until its budget is met; the last instruction may overshoot.
Both accumulate `cycles`. `restore(_:)` clears the clock count and halt state
without accessing memory. The owner must restore memory and devices alongside
the registers. CPU instances require a single execution owner.

Default registers are deterministic conveniences, not a hardware reset model.
External interrupts are not implemented. BRK, RETI, EI and DI are implemented
as instructions. SLEEP and STOP follow the corpus's seven-clock finite
observation, then set `stopped`. Further `step()` calls do nothing;
`run(cycles:)` advances idle bus clocks while held. Wakeup and hardware reset
remain outside this API.

## Verification

The independent [SingleStepTests corpus](https://github.com/SingleStepTests/ProcessorTests/tree/bb11756436da8fd16cce86aef63dc6725f48836f/spc700)
was generated by David Schneider's JSMoo. It is pinned at
`bb11756436da8fd16cce86aef63dc6725f48836f`. The Swift port passes all 256,000
cases: final registers and listed RAM bytes, cycle counts, and every recorded
read/write/wait address and defined value. Unspecified read values are not
compared. This is emulator-conformance evidence, not hardware measurement or
proof of complete APU/audio fidelity.

Default tests include eight cases per opcode, selected at fixed indices spread
across each upstream file (2,048 total). Provenance and SHA-256 are beside
`Resources/SPC700/vectors.json`. The full corpus stays in a local reference
checkout. Reproduce/check the sample and run the full suite with:

```sh
python3 macos_studio/tools/prepare_spc700_vectors.py \
  re_workspace/refs/processor-tests/spc700/spc700/v1 --check
CHRONOFORGE_SPC700_VECTORS="$PWD/re_workspace/refs/processor-tests/spc700/spc700/v1" \
  swift test --package-path macos_studio --filter SPC700Tests
```

For a fresh checkout, obtain the pinned corpus without the other processors:

```sh
git clone --filter=blob:none --no-checkout \
  https://github.com/SingleStepTests/ProcessorTests.git \
  re_workspace/refs/processor-tests/spc700
git -C re_workspace/refs/processor-tests/spc700 sparse-checkout set spc700
git -C re_workspace/refs/processor-tests/spc700 checkout \
  bb11756436da8fd16cce86aef63dc6725f48836f
```

The master gate checks the sample against this pinned checkout and runs the full
corpus when installed. Otherwise the sample still runs and the extended test
is explicitly skipped. An explicitly supplied invalid path or malformed case
fails the extended test.

Known limits inherited from the reference: MOVW dp,YA uses the corpus's five
clocks (the Nintendo instruction table says four); halt observation differs
from the table's nominal three clocks. These choices do not establish physical
hardware behavior. The reference's `conformance/divergences.json` records these
discrepancies and its remaining hardware-validation limitations.

## SPC snapshots

`SPCFile` reads and writes complete v0.30 snapshots using the
[published format](https://snesmusic.org/files/spc_file_format.txt): CPU
registers, 65,536 RAM bytes, 128 DSP registers and 64 extra RAM bytes underneath
the IPL overlay. Extra RAM is **not** the IPL program. Reserved bytes, ID666
header bytes and the trailer are preserved exactly, including binary tags and
opaque xid6 extensions. Tags are not interpreted; trailer validity is not
checked. New snapshots have no ID666 tag.

The parser requires the complete 66,048-byte base file and rejects unsupported
headers, truncation and invalid array sizes. Short 0x10180-byte dumps accepted
by some players are not supported. SPC snapshots omit timer phases and DSP
internal history, so they cannot restore exact execution mid-cycle.

Inspect a snapshot without executing it:

```sh
macos_studio/.build/debug/chronoforge music spc-info snapshot.spc --out info.json
```

The JSON contains CPU registers, memory-region hashes and trailer length.
Errors preserve existing output; input and output must differ.

## Normal-speed S-SMP bus and driver execution

`SSMPBus` connects the CPU to 64 KiB RAM, directional host/APU ports, three
timers, an optional caller-supplied 64-byte IPL overlay, and an `SSMPDSPPort`
endpoint. CPU reads/writes and idle cycles advance the timers and endpoint.
Host port operations consume no SMP clocks. Timer outputs are four-bit and
read-clear; enabling resets divider/output but preserves the free-running
prescaler. CONTROL clears incoming port pairs without clearing outgoing replies.
DSP addresses with bit 7 set read the mirrored register and ignore writes.

The implementation follows the existing CPU's **access before clock** contract.
It is a deterministic normal-speed model, not a physical subcycle timing model.
Construction zeros timer phases and MMIO latches independently of initial RAM;
it does not restore an SPC snapshot or reproduce hardware power-on state.
Nonstandard TEST writes and enabling an absent IPL produce a sticky bus fault.
Callers must inspect `fault` after each instruction and stop; the nonthrowing CPU
interface otherwise continues counting accesses after the bus has frozen.

`CTSPCDriver.check` copies the six payloads identified by the ROM's boot tables
into ARAM and executes the original driver at `$0200`. The CLI requires the
verified USA 1.0 ROM SHA-256 because its checkpoints are revision-specific:

```sh
macos_studio/.build/debug/chronoforge music driver-check re_workspace/ct_clean.sfc \
  --out driver-check.json
re_workspace/.venv/bin/python macos_studio/tools/verify_ssmp_driver.py
```

The diagnostic reaches the first main-loop entry `$0299`, checks initialized
RAM/DSP values, sends an echo-only command, then sends `$FD` to exercise the
driver's DSP-write handler. It uses a register-only DSP probe. The first entry
takes 85,396 clocks in the chosen zero-state model: initialization waits for
five timer1 ticks. Execution has a 250,000-clock budget (instruction-boundary
checks; may overshoot by one instruction). Timeouts and bus faults fail.

Without `--ipl` this is **direct-load driver execution**, not song loading,
synthesis or playback. The evidence and reproduction commands are in the local
workspace (`re_workspace/reports/ssmp_evidence_20261019.md` and
`re_workspace/manifests/ssmp_driver_verification.json`).

## IPL upload

`SPCIPLHost` drives the boot ROM's transfer protocol from the host side of the
ports, following CT's `Audio_Boot` sender (ChronoRET `bankC7.asm`): wait for
`$AA $BB`; send each block's ARAM address in ports 2/3 with token and nonzero
command `$CC` (first) or *last counter + 4, 0 replaced by 1* (later); send each
byte in port 1 with its 8-bit counter in port 0 and wait for the echo; finally
send the entry address with command 0, wait for the echo, and write port 0 = 0.
The host stops **before** the entry instruction executes and only then compares
every uploaded byte with RAM, because the IPL echoes a byte before storing it.
If the CPU leaves `$FFC0...$FFFF` anywhere except the entry it fails at once.
Blocks must not overlap and must lie in `$0200...$FFBF`; total and per-wait
cycle budgets, a stopped CPU and bus faults all fail. A host instance uploads
once. Host writes happen between whole SMP instructions; 65816 timing,
power-on RAM and subcycle port races are not modeled.

No IPL image is bundled. Supply a local 64-byte image:

```sh
macos_studio/.build/debug/chronoforge music driver-check re_workspace/ct_clean.sfc \
  --ipl /path/to/ipl.rom --out driver-check-ipl.json
CHRONOFORGE_IPL_ROM=/path/to/ipl.rom \
  re_workspace/.venv/bin/python macos_studio/tools/verify_ssmp_driver.py --lane ipl
```

With the known image (SHA-256 `c95f88b2…278f`) the six CT payloads, 13,884
bytes, upload with 13,891 acknowledgements in 350,140 SMP clocks (token chain
`$CC $F2 $03 $04 $27 $17`, start token `$17`), match the ROM before `$0200` runs,
and the driver then passes the same checks as the direct load. Upload and
post-entry clocks are reported separately; the first `$0299` entry takes 85,322
post-entry clocks (85,396 when direct-loaded: the timer prescaler phase differs).
One extra check applies: the IPL's start echo stays in CPUIO0 until the driver's
first main-loop pass writes 0. `SPCIPLHostTests` covers the protocol with a
firmware-free receiver model (counter wrap, zero-token correction, stores
committed after their echo, corruption, wrong entry, budgets, stop/fault, input
validation) and runs the real-image lane only when `CHRONOFORGE_IPL_ROM` is set;
without it those tests skip as UNVERIFIED, and a set but invalid path fails.

## Remaining playback work

1. Extend the normal-speed bus beyond its documented limits only with reference
   evidence: physical edge timing, TEST modes and hardware reset/restore.
2. S-DSP: BRR history, Gaussian interpolation, envelopes, noise, pitch
   modulation, key-on/off timing and echo. Claude's Gaussian-table uncertainty
   is still unresolved; use a named source and independent checks.
3. CT host: samples and songs loaded through the verified driver protocol.
   The IPL boot transfer, driver initialization and two command paths execute;
   the sample/song transfer commands remain unfinished.
4. Generated SPC snapshots and rendered PCM compared against installed libgme,
   accounting for gain, filters and echo setup.
5. Bounded CLI rendering and Studio playback through AVFoundation.

There is no audible playback or new Play control in this milestone.
